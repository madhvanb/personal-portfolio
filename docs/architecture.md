# Architecture

## Principles

1. **Content is data.** Pages never contain your projects or jobs directly;
   they read them from `src/content/` and `src/data/`. Updating the site
   means editing data, not markup.
2. **One source of truth per thing.** Identity → `src/config/site.ts`.
   Visual values → `src/styles/tokens.css`. Content rules →
   `src/content.config.ts`. Queries → `src/lib/content.ts`.
3. **Fail at build time, not in production.** Schemas validate content,
   TypeScript (strictest mode) checks code, and a link checker scans the
   output. Broken things stop the build.
4. **Static by default.** Every page is pre-rendered HTML. The only
   JavaScript sent to visitors is the theme toggle, the project filter and
   the résumé print button, and the pages work without it.

## Layout

```
astro.config.ts           Site URL, base path, Markdown + maths + code setup
src/
  config/site.ts          Name, email, links, nav: identity in one place
  content.config.ts       Schemas: what fields each content type must have
  content/
    projects/*.mdx        Case studies → /projects/<file-name>/
    writing/*.mdx         Posts → /writing/<file-name>/
  data/*.yaml             Experience, education, publications, skills
  lib/
    content.ts            All content queries (filtering drafts, sorting)
    url.ts                href(): adds the base path to internal links
    dates.ts              All date formatting
    markdown/katex.ts     Renders LaTeX to HTML at build time
    markdown/shiki-mono.ts  Black-and-white code highlighting themes
  styles/
    tokens.css            Design tokens: colours, type scale, spacing
    global.css            Reset, base elements, utilities
    prose.css             Typography for rendered Markdown
    print.css             Résumé print / PDF output
  layouts/
    BaseLayout.astro      Every page: <head>, header, main, footer
    ArticleLayout.astro   Case studies and posts
  components/             Reusable building blocks (see below)
  pages/                  One file per route (see below)
scripts/check-links.mjs   Post-build broken-link checker
.github/workflows/ci.yml  Verify on every push; deploy main to Pages
```

## Routes

| File                          | URL               |
| ----------------------------- | ----------------- |
| `pages/index.astro`           | `/`               |
| `pages/projects/index.astro`  | `/projects/`      |
| `pages/projects/[slug].astro` | `/projects/<id>/` |
| `pages/writing/index.astro`   | `/writing/`       |
| `pages/writing/[slug].astro`  | `/writing/<id>/`  |
| `pages/resume.astro`          | `/resume/`        |
| `pages/404.astro`             | any unknown URL   |
| `pages/rss.xml.ts`            | `/rss.xml`        |
| `pages/robots.txt.ts`         | `/robots.txt`     |

The sitemap (`/sitemap-index.xml`) is generated by `@astrojs/sitemap`.

## Components

Each component has a header comment describing what it's for and how to use
it. Summary:

| Component               | Purpose                                                       |
| ----------------------- | ------------------------------------------------------------- |
| `Head`                  | Title, SEO and social meta, favicon, theme bootstrap script   |
| `Header`, `Footer`      | Site chrome                                                   |
| `ThemeToggle`           | Light/dark switch, remembers choice, follows OS otherwise     |
| `Section`               | Numbered section with thick top rule and optional action link |
| `PageTitle`             | Big title for index pages                                     |
| `EntryList`, `EntryRow` | Ruled, hover-inverting list of projects or posts              |
| `ExperienceItem`        | A job, `compact` or `full` variant                            |
| `PublicationItem`       | A paper, bolds your name in the authors                       |
| `TagList`               | Boxed tag labels                                              |
| `MetricList`            | Grid of headline numbers                                      |
| `LinkGroup`             | Paper / Code / Demo / Model ... buttons                       |
| `FormattedDate`         | `<time>` with consistent formatting                           |
| `Callout`, `Figure`     | For use inside MDX                                            |

## Rules that keep things from breaking

- **Never write `href="/something"`.** Use `href('/something/')` from
  `@/lib/url`. The site is served under `/personal-portfolio/`, and the link
  checker fails the build on links that skip the base path.
- **Never call `getCollection()` in a page.** Use the functions in
  `src/lib/content.ts`, so draft filtering and sort order stay consistent.
- **Never put a raw colour or pixel size in a component.** Use a token.
- **Import with `@/`** (e.g. `@/components/Section.astro`), not `../../`.
  Files can move without breaking imports elsewhere.

## Adding a page

1. Create `src/pages/talks.astro`.
2. Wrap it in `<BaseLayout title="Talks">…</BaseLayout>`.
3. Add `{ label: 'Talks', path: '/talks/' }` to `nav` in `src/config/site.ts`.

## Adding a content type

1. Define a collection with a schema in `src/content.config.ts`.
2. Add a query function to `src/lib/content.ts`.
3. Use it from a page. Run `npm run check`; TypeScript now knows every field.

## Tooling

| Tool           | Config               | Role                                   |
| -------------- | -------------------- | -------------------------------------- |
| TypeScript     | `tsconfig.json`      | Strictest settings; `@/*` path alias   |
| `astro check`  | n/a                  | Type-checks `.astro` files and content |
| ESLint         | `eslint.config.js`   | Bugs + accessibility (jsx-a11y) rules  |
| Prettier       | `.prettierrc.json`   | Formatting; no style debates           |
| EditorConfig   | `.editorconfig`      | Same indentation in every editor       |
| GitHub Actions | `.github/workflows/` | Runs `npm run verify`, deploys `main`  |

## Dependency notes

- `package.json` `overrides` pins `katex` and `minimatch` to patched versions
  so `npm audit` stays clean. Check whether they're still needed when
  upgrading.
- `eslint-plugin-jsx-a11y-x` is used instead of `eslint-plugin-jsx-a11y`
  because the original doesn't support ESLint 10 yet.
- Upgrade everything with `npx npm-check-updates -u && npm install`, then
  `npm run verify`.
